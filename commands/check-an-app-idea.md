# Check an App Idea

The 30-minute verdict on one named app idea. Loads
`app-idea-discovery` for the full method; this file is the run order.

## 1. Write the problem, not the solution (2 minutes)

One sentence: who has what problem, how often, what it costs them in time
or money. If you cannot write this sentence, stop — the idea is not ready
to check.

## 2. Find the 3 closest paid competitors (5 minutes)

- [ ] 3 paid products that do this job (an app, a service, a paid ledger)
- [ ] If nobody pays for anything in this space, that is a signal — note
      it, do not ignore it

## 3. Mine their 1–3-star reviews (10 minutes)

- [ ] Read recent 1-star reviews (dealbreakers) and 2–3-star reviews
      (feature gaps) for each competitor
- [ ] Capture raw quotes in the users' own words — do not paraphrase
- [ ] Rewrite each complaint as a job-to-be-done: "When I [situation], I
      want to [action], so I can [result]"
- [ ] A theme across SEVERAL competitors is a market gap; a theme in one
      app is one app's bug

## 4. Mine community complaints (5 minutes)

- [ ] Search Reddit, Facebook groups/pages, YouTube comments for
      "[category] + problem / hate / wish / alternative / too expensive"
- [ ] For Bangladesh: Facebook groups and page comments in Bengali are
      often the richest source
- [ ] Same complaint from many people over time = pattern; one person's
      wish = data point

## 5. Check search demand (3 minutes)

- [ ] Google Trends: is interest in the problem stable, growing, or
      declining? A declining trend kills the idea.
- [ ] Demand last, because it is the easiest signal to misread

## 6. Score it

PAID / PAIN / GAP — at least two of three to proceed:

- **PAID** — people already pay for something that does this job
- **PAIN** — people complain about the current options, recently and
  repeatedly, in their own words
- **GAP** — a specific niche is ignored, overcharged, or buried in
  features it does not need

Plus solo feasibility (1–5): one or two core flows, buildable and
maintainable by one person — and your own access to the audience (can you
reach and talk to the users?).

## 7. Verdict

- **GO** — evidence strong. Next step: 10–20 problem interviews (strangers,
  not friends/family), then a smoke-test landing page.
- **DIG DEEPER** — one more test needed. Name the test and what result
  would change the verdict.
- **DROP** — evidence weak. Say why in one sentence and move on.

Write the verdict up in `templates/app-idea-one-pager.md` — one page per
idea, so the decision is on record.
